Turns defects you hit while using gajae-code (gjc) into quests, and lets only the ones a human accepted become upstream contributions. Detection is automated; judgement and transmission are entirely human.

The flow

The order is fixed. Highlighted steps are the human's, and nothing reaches the remote before them.

01

Detect

Classified as crash, session misbehavior or static defect. No periodic batch, no continuous polling.

02

Validity

Already landed? Still present on current dev? Reproduces with a clean HOME? Crash signature in the journal?

03

Grade & exclude

Only crashes, data loss and live outages are HIGH. The exclusion view drops candidates before intake.

04

Intake — human

Raised as a card with an eleven-slot report and a Decision block. Accept, reject or hold is the human's call.

05

Three gates

maintainer_prohibition → freeze → contract/state. Short-circuits on first failure.

06

Transmit — human

Push, PR and issue creation only after approval, and only for that head sha. No auto-submission.

07

Ledger & notes

One five-field row is updated and observations appended. Remote state is derived, never copied.

Why it is built this way

Say "find bugs and open PRs" and you get a pile of draft PRs and logging cleanups polluting the maintainer's queue.

human gates2

Intake and transmission are different doors

① intake — is this worth being a quest? ② transmission — do we actually push it? Passing ① does not authorize ②, and the skill performs neither on your behalf.

slot1

One thing in flight

A second accepted row cannot exist. No WIP count, lot lifetime or token budget — the structure blocks it instead of a number.

gates3, ordered

Blocked means zero remote

A prohibition notice, a freeze or a damaged state shuts both the PR path and the crash-report path. Detection, intake and local records keep working meanwhile.

pre-intake4 checks

Already fixed is not a quest

Your install is always older than upstream dev. Landing status, the live path on current dev, a clean-HOME repro and the crash signature are checked before grading — fail any and no card is raised.

minimality1 defect

Do not borrow design authority

One PR, one defect, minimal change. If more than one answer is defensible it is a product decision, so it goes out as an issue rather than code.

If blockers survive two independent reviews, stop — a third redesign proves the design is someone else's.

ledger5 fields

No double bookkeeping

quest_id · source · state · pr · closure_cause. No sixth column, no pseudo-state like candidate. Current remote state is derived from read-only gh.

freeze3 predicates

Detect the freeze and stop

Batch closes without review · do not open-style wording · several of my items closed within 24 hours. Any one drops transmission to zero and raises a local card.

It clears only when the owner reviews or merges again — never by elapsed time.

decision block

A list of options is not a card

Every option carries what happens if you pick it, its upside and its downside, plus one recommendation and its basis. If the basis is thin, say what is missing.

Install

One file. The skill never changes your configuration — you turn it on.

# install the skill
mkdir -p ~/.gjc/agent/skills/gjc-quest
curl -fsSL https://raw.githubusercontent.com/yazzang-homelab/gjc-quest/main/SKILL.md \
  -o ~/.gjc/agent/skills/gjc-quest/SKILL.md

# config.yml — both must be true to load
skills.enabled: true
skills.enablePiUser: true

# invoke (from a new session)
/skill:gjc-quest
  • Turning the settings on does not affect the current session. Invoke from a new one — that is the first thing to check when /skill:gjc-quest looks like it does not exist.
  • Aliases: gjc quest · quest scan · scan gjc defects · gjc 퀘스트 · 결함 퀘스트
  • The ledger and observation notes attach to a single file, ~/.gjc/agent/state/gjc-quest-ledger.md. No new JSONL is created.
  • The observation notes are local-only. This repository ships none of that content — the exclusion view is an empty view each user fills from their own observations.

What it will not do

No exception paths.

Auto-submission — push, PR and issue creation only after approval, only for that head sha.
Periodic batches or polling — cron dies with the session. Only a one-shot report at a human-specified time is allowed.
Asking permission — never "may I open this?" to the maintainer. Only evidence-carrying out-of-scope defect issues.
Reimplementation — it wraps gjc crash report instead of rebuilding signatures or issue creation.
Config edits or hooks — the skill does not touch config.yml.
Rewriting damaged state — duplicated or corrupt sections are held and reported.
This is an unofficial third-party skill with no affiliation to upstream. It targets Yeachan-Heo/gajae-code, the base branch is always dev, and it assumes gjc-only surfaces such as gjc crash report, gjc notify and the PR verdict block. Using it against another repository means rewriting those parts. Whether a contribution is accepted is always the maintainer's call — this document is a procedure, not an authorization.
